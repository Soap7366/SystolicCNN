# 完整 CNN 后续交接清单

日期：2026-10-25。范围：PYNQ-Z2、输入 `[1,1,64,64]` INT8、三层卷积 `1→8→16→32`、每层 ReLU/2×2 Pool、GAP、FC `32→1`，输出一个 INT32。

## 当前实现边界

当前工程用于协议与候选整数算术验证。**尚无完整的 Conv、padding、CNN 调度控制器和整网连接实现。** 现有 MAC、requant、Pool、GAP、FC 候选算术单元即使各自测试通过，也不等于完整 CNN 已实现，更不代表与真实碰撞风险模型一致。AXIS_SUM 仅为4096B输入、4B输出的求和链路验证模块。

## 继续完整 CNN 最少需要补充的数据

| 交付项 | 最低要求 |
|---|---|
| 冻结模型与拓扑 | 唯一 `model_id`；明确 Conv 为交叉相关还是翻核卷积、stride/padding、层顺序、融合位置与张量布局。 |
| 真实权重与偏置 | Conv1/2/3/FC 共 **5,864个 INT8 权重**（72/1,152/4,608/32），共 **57个 INT32 Bias**（8/16/32/1）。提供形状、OIHW或其他显式布局、扫描顺序、小端及补码说明；不接受随机值作为真实模型参数。 |
| 完整数值规则 | 每层输入/输出及权重的 scale、zero point、量化轴；每层/输出通道整数乘数 M、shift、舍入规则、乘积/累加位宽、溢出处理及 clamp；Bias尺度、ReLU阈值、padding量化零值、GAP除64与重定标顺序、FC输出是否raw INT32。 |
| 确定性预处理 | 原图、可运行预处理代码、依赖版本及对应的 **4,096字节 INT8** 输出；锁定解码、EXIF方向、灰度、resize/antialias、裁剪或补边、归一化、量化舍入、行优先顺序。 |
| 整数金模型与 Golden | 可重跑的位精确参考程序；固定输入和逐层 Conv INT32累加、requant/ReLU/Pool INT8、GAP sum/out、最终 **INT32 logit**。覆盖零值、极值、梯度、脉冲、棋盘格、负数算术及真实道路样本。 |
| 版本与完整性 | manifest 记录文件 SHA-256、shape/dtype/layout、训练/量化/推理框架及精确版本、量化后端、导出脚本版本、预处理版本与测试集版本。权重、量化参数和 Golden 必须属于同一模型。 |
| 输出语义 | 最终 logit scale/zero point、正负类别含义、概率/整数阈值、等于阈值时归属。示意图中的 `0.0001237` 不能直接当作正式scale。 |

模板占位符、缺失参数或不匹配哈希应阻止正式模型构建；不得静默填入 scale=1、zero point=0 或猜测舍入规则。

## 模型交付后的实现与验证顺序

1. 检查部署包、manifest和参数完整性；在电脑重跑整数金模型，复现全部Golden，并逐字节核对原图→4096B。
2. 按冻结布局实现权重/特征存储、padding和Conv引擎；依次集成Conv1→ReLU→Pool、Conv2、Conv3，再接GAP与FC。每阶段对比INT32累加与INT8结果，首次差异逐元素定位。
3. 实现CNN调度控制器、层间缓冲和AXIS收发壳；完成整网testbench，检查最终INT32与Golden严格一致，并覆盖输入间断、背压、连续帧、非法包与各阶段复位。
4. 对完整CNN和PS7/DMA系统综合、布局布线；检查资源、存储推断、时序、DRC和复位连接。不能用算术单元或AXIS_SUM报告代替整网报告。
5. 从同一通过检查的工程构建导出配套 `.bit` / `.hwh`，记录工具/IP版本、硬件构建ID及模型哈希。
6. 板上依次确认基础DMA链路与4096B→4B返回，再运行真实CNN；固定样本逐个核对原始INT32，至少连续 **100帧** 无死锁、串帧或缓冲覆盖。分别记录PS预处理、DMA、PL计算与端到端时间。
7. 最后在独立数据集评价准确率、召回率、误报/漏报与阈值；硬件复现模型与模型应用效果分别报告。
